# SwiftHTML 0.2.0 — Release Notes

**Release preparation date:** 2026-11-21  
**Status:** Release candidate; **the public 0.2.0 Git tag and GitHub Release are not yet created**.  
**Code baseline already integrated:** [`8a1d75b206d87538dda2be304365e5a50bf0bf31`](https://github.com/ThorFuchs/Swift-HTML/commit/8a1d75b206d87538dda2be304365e5a50bf0bf31).  
**Final published source:** must be the exact new `main` commit containing these release documents, after that SHA has passed its own release CI. Do not tag the historical baseline accidentally.

## Summary

SwiftHTML 0.2.0 turns the small HTML parsing and editing facade into an
**inspectable structural DOM API** while preserving its existing consumers.
The public API now exposes owner-retaining, live node references for text,
elements, comments and data, plus bounded, iterative, depth-first traversal.

The parser remains the source-audited, fixture-free SwiftSoup 2.14.4 backend.
SwiftHTML is not a browser, HTML sanitizer or unrestricted stream parser.

## What's new

- `HTMLNode` and `HTMLNodeKind`: live document, element, text, comment,
  data and other-node inspection without leaking vendored backend types.
- `HTMLDocument.rootNode` and `HTMLElement.node`: bridge existing selection
  and editing flows to structural inspection without copying the DOM.
- `HTMLNode.parent`, `nextSibling`, `previousSibling`, `childCount`,
  `child(at:)` and `children(maximumCount:)`: ordered navigation with explicit
  allocation limits.
- `HTMLNode.wholeText`, `commentText` and `rawData`: distinguish actual
  parsed text, comments and script/style-like data without conflating them
  with normalised descendant text.
- `HTMLNode.walk(limits:_:)`, `HTMLTraversalLimits`,
  `HTMLTraversalError`, `HTMLTraversalReport`: iterative preorder traversal,
  finite postparse node/depth budgets, cooperative cancellation and a
  completed-traversal summary.
- New structural DOM tests, external consumers, DocC guides and reproducible
  macOS, Linux and WebAssembly WASI qualification gates.

## Swift, platforms and compatibility

**Breaking requirements compared with 0.1.1:**
- Swift **tools 6.4 minimum**, Swift 6 language mode for SwiftHTML's public
  target. Release qualification is on **Swift 6.4.2**.
- The vendored backend is still compiled in Swift 5 **language mode** using
  the same Swift 6.4 compiler; no separate Swift 5 toolchain is required.
- Apple minimum deployment targets are **macOS 15, iOS 15, tvOS 15,
  watchOS 9, Mac Catalyst 15 and visionOS 1**.
- Linux and WASI do not use those Apple deployment floors.

Existing 0.1.1 public APIs remain available with the same names. This is an
additive source API update **for consumers that meet the new toolchain and
platform minimums**; it is not a claim that old toolchains can build 0.2.0.

## Example: ordered, bounded DOM traversal

```swift
import SwiftHTML

let doc = try HTMLDocument.parseFragment(
    "<section>before <b>bold</b> after<!--note--></section>"
)
let section = try doc.select("section").first!
let limits = try HTMLTraversalLimits(maximumNodes: 32, maximumDepth: 8)
let report = try section.node.walk(limits: limits) { node, depth in
    switch node.kind {
    case .element: print(depth, node.element?.tagName ?? "")
    case .text: print(depth, node.wholeText ?? "")
    case .comment: print(depth, node.commentText ?? "")
    default: break
    }
}
print(report.visitedNodes)
```

Node views are **live, non-Sendable** references to a mutable document.
Do not mutate the tree inside a traversal callback. It detects some
child-count changes, but does not guarantee mutation detection for reorderings
or text edits. The finite traversal budget applies **after parsing**, not to
parser peak memory, input bytes or CPU time. Bound untrusted input separately.

## WASI portability and source provenance

The vendored SwiftSoup 2.14.4 Sources+LICENSE inventory excludes upstream tests
and unrelated third-party webpage fixtures. The audited, reversible
WASI-only `Mutex.swift` adaptation uses Foundation `NSLock` instead of
unavailable pthread APIs. `Vendor/SwiftSoup/UPSTREAM.json` records the
transformations; `Scripts/verify-upstream.py` reverses them and verifies
original SHA-256 hashes. This is a controlled port, **not unmodified upstream
source**.

SwiftHTML's own code remains Apache-2.0. The SwiftSoup/jsoup and LRUCache
backend code retains MIT notices, packaged as SwiftPM resources. These notices
must accompany applicable source and binary redistributions. The source
inventory and CI checks are **not a legal opinion**.
See [third-party provenance](../THIRD_PARTY.md).

## Installation

**After the real 0.2.0 tag is published**:

```swift
.package(url: "https://github.com/ThorFuchs/Swift-HTML.git", from: "0.2.0")
```

Then depend on:

```swift
.product(name: "SwiftHTML", package: "Swift-HTML")
```

Until the public 0.2.0 tag exists, `0.1.1` remains the newest published
release. Never market the development branch as a published immutable release.

## Upgrade from 0.1.1

1. Upgrade the compiler and tools to Swift 6.4+ (qualified on 6.4.2).
2. Ensure the application's declared platform minimums meet the new floors.
3. Advance to the released `0.2.0` tag when available.
4. Existing parse/select/edit calls need no source change; adopt structural
   traversal explicitly where needed. Continue to avoid using normalized
   `HTMLElement.text()` to reconstruct mixed original text-node ordering.
5. Retain all applicable license notices in any redistributed artifact.

## Out of scope

No HTML sanitation, arbitrary XML profile, web/DOM execution, JavaScript,
global CSS/URL trust policy, parser-time hard resource enforcement, original-byte
source ranges, implicit Sendable, universal WASI/browser compatibility,
or full SwiftSoup API mirroring.
