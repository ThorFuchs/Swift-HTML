# SwiftHTML 0.2.0 — Publication playbook

**Status:** ready for final, exact-SHA release verification; **do not infer that the
0.2.0 public tag or GitHub Release already exists** from this file. SwiftHTML
0.1.1 is the last confirmed published release as of 2026-11-21.

This is a package release (source + existing generated GitHub archives).
The SwiftPM public product remains `SwiftHTML`. No additional license-bearing
binary artifacts should be uploaded without their own distribution audit.

## Preconditions

1. Merge the 0.2.0 documentation-preparation pull request only after its
   exact-head Linux, macOS 15, WASI, and DocC workflows pass.
2. Retrieve the **new `main` commit SHA after the merge**. Record the full SHA,
   not just its abbreviated display. Confirm the repository did not advance.
3. Confirm a post-merge successful `main` run on **that exact SHA** for:
   - macOS 15 Intel: Swift 6.4.2, 22 tests, optimized build, real consumer,
     synthetic exact-SHA versioned consumer and bundled notices.
   - Linux x86_64: Swift 6.4.2 debug/release tests, release build,
     real consumer, source/notice checks and synthetic versioned consumer.
   - WASI: Swift 6.4.2 SDK build, public consumer link **and execution**,
     including structural traversal.
   - DocC: warnings-as-errors and successful GitHub Pages deployment.
4. Record any **skipped** jobs: Xcode 27 simulator cross-build remains skipped
   unless `HAS_MACOS27_RUNNER` is configured. That is *not* a green simulator test.
5. Run `Scripts/check-release-contract.py`, `verify-upstream.py` and
   `verify-notices.py` in normal CI as part of the source-bound evidence.
6. Confirm `0.2.0` tag does not already exist; if it does, inspect its
   target and do **not** retag or force-push.
7. No other changes between qualified commit and tagging. If main advances,
   repeat exact-SHA qualification before publication.

## Tag and publish (maintainer GitHub UI)

1. Open [Swift-HTML Releases](https://github.com/ThorFuchs/Swift-HTML/releases)
   and choose **Draft a new release**.
2. Choose tag **`0.2.0`**, creating it **at the full, verified `main` commit
   SHA** — do not rely on a moving default branch.
3. Set title **SwiftHTML 0.2.0**; keep "Set as a pre-release" **off** only
   if all release gates passed.
4. Paste the release body below; verify its references and the exact source.
5. Do not upload an unreviewed app, compiled library or tarball. GitHub-generated
   source archives contain the included license texts, but third-party
   redistribution duties still apply.
6. Publish, then inspect the tag/release in a clean external session.

### GitHub Release body

> source-audited HTML parser. Live `HTMLNode` references preserve parsed
> element/text/comment/data node kinds and sibling order. An iterative
> `walk(limits:_:)` traversal adds finite postparse node/depth limits,
> cooperative cancellation and a completion report.
>
> **Requirements:** Swift tools 6.4+ (qualified on 6.4.2). Apple deployment

>
> The vendored SwiftSoup 2.14.4 source excludes upstream test/web fixtures.
> A precise WASI-only `NSLock` portability adaptation is documented and
> reversible for provenance verification. SwiftHTML remains Apache-2.0 with
> bundled SwiftSoup/jsoup and LRUCache MIT notices.

## Post-publication checks

- Verify public `0.2.0` tag target equals the qualified commit. Compare
  GitHub Release's target and repository `main` explicitly.
- From a **fresh** Swift 6.4.2 consumer checkout, resolve:
  `.package(url: "https://github.com/ThorFuchs/Swift-HTML.git", exact: "0.2.0")`,
  import `SwiftHTML`, parse mixed nodes and perform bounded traversal. Save
  the exact `Package.resolved` revision and results; the current synthetic
  local `0.0.1` test is not a substitute for this public resolution.
- Verify exported source license, vendor notices, DocC version `0.2.0`,
  tag Git tree, release contents, and published attribution.
- Update README and DocC public-install examples from 0.1.1/pending-tag
  wording to `from: "0.2.0"` **after** the public tag exists, without changing
  the released source history. This is a separate postpublication docs PR;
  the tagged sources remain reproducible with the prepublication wording.
- Close [Swift-HTML #1](https://github.com/ThorFuchs/Swift-HTML/issues/1)
  after successful release and the public consumer verification.
- Hand off the versioned dependency to
  [Research Explorer RE-08](https://github.com/ThorFuchs/Swift-MCP-Server/issues/42).
  That repo's exact MediaWiki normalization parity and license audit are
  **separate** release acceptance conditions.

## Stop conditions

Do not publish when the source SHA changed, a required native or WASI job
failed, a required test was disabled to hide a failure, the upstream
source/notice verifier failed, or source/provenance/DocC versions disagree.
A skipped Xcode 27 matrix is a *disclosed scope limitation*, never evidence
of passing Apple platform qualification.
